# Scala
It is the programming language of the Apache Spark
Scala is a programming language that combines Object-Oriented Programming (OOP) and Functional Programming (FP).

- Why Scala?
Because Spark programs can be written using Scala.

- REPL
It stands for:
    R — Read
    E — Evaluate
    P — Print
    L — Loop
It is an environment where we enter one command, Scala evaluates it immediately, displays the result/error, and waits for the next command.

Example:
    scala> 10 + 20
Scala immediately evaluates it:
    res0: Int = 30

- Why is REPL useful?
Instead of writing:
    program → compile → run → check result
you can simply do:
    command → result

# val, var & Type Inference
Scala gives us two important ways to create these bindings:

          Variables
             │
       ┌─────┴─────┐
       ▼           ▼
      val         var
   Immutable    Mutable

- val — Immutable
Meaning:
    val creates an immutable binding.
Once you assign a value, you cannot reassign that name to another value.

Example:
    val age = 21
    println(age)
    age = 25 // Error

- var — Mutable
var is the opposite.
var creates a mutable binding whose value can be changed later, provided the new value is compatible with its type.
Example:
    val age = 21
    println(21) // 21
    age = 25
    println(25) // 25 (No error)

- val vs var
This is a must-remember CA table:

val	                    var
Immutable	            Mutable
Cannot be reassigned	Can be reassigned

- Type Inference
Look at this:
    val x = 10
We didn't write:
    val x: Int = 10

So how does Scala know x is an Int?
That's where Type Inference comes in:
    Type inference allows the Scala compiler to determine the type of a value from the expression assigned to it.

- Explicit Type Declaration
val age: Int = 21
val name: String = "Amandeep"
var marks: Double = 85.5

Without explicit type:
    val age = 21
Scala figures out:
    age → Int
With explicit type:
    val age: Int = 21
You tell Scala:
    age → Int

# List (Immutable)

- Adding elements to List

val list2 = list1 :+ "p" // [ a b c d e p ]

(ii) +: -> append at the beginning
val list3 = "l" +: list2 // w,a,b,c,d,e,p

(iii) prepend

(iv) ::: -> Concatenate lists
val list5 = list4 ::: list3

# Functions
Syntax:
    def functionName(parameter: Type): ReturnType = {
        // body
    }
For example:
    def squ(x: Double): Double = {
        x * x
    }

Calling the function
squ(5)
OR
println(squ(5))

- Multiple Parameters
A function can accept multiple Parameters
def squSum(x: Double, y: Double) = {
    squ(x) + squ(y)
}
Now:
    squSum(3, 5)

means:
    squ(3) + squ(5)
    ↓
    9 + 25
    ↓
    34
So:

    34.0

- Return Type
You can explicitly specify the return type:
    def square(x: Int): Int = {
        x * x
    }
Here:
    Input  → Int
    Output → Int
But Scala can often infer the return type:

    def square(x: Int) = {
        x * x
    }

# Recursive Functions
A recursive function is a function that calls itself.
def factorial(x: Int): Int = {
    if (x <= 1) 1
    else x * factorial(x - 1)
}

# Higher Order Functions
A normal function takes data as input.
But
A Higher-Order Function (HOF) is simply a function that can take another function as an argument or return a function.

For example:-
def square(x: Int): Int = {
    x * x
}
Now imagine we create:
    def calculate(f: Int => Int, x: Int): Int = {
        f(x)
    }
Here calculate() takes two things:
    f -> a function
    x -> an Integer
So,
    calculate(
        function,
        number
    )
That's a Higher Order Function

- What does Int => Int mean?
A function that takes an Int and returns an Int
For example:
    def square(x: Int): Int = x * x
This is:
    Int → Int

- Passing the function
calculate(square, 5)
Here we wrote:
    square
NOT:
    square(5)

Why?
    Because we want to give the function itself to calculate().

Think of it like this:
    square
    ↓
    "Here is the function.
    You decide when to use it."

Then calculate() does:
    f(x)

which becomes:
    square(5)
which gives:
    25

UNIT 6

1. What is a Spark session?
A SparkSession is the entry point for working with Spark. We use it to read data and perform Spark operations.

2. SparkSession.builder.getOrCreate()
Gets an existing Spark session or creates one if it does not exist.

3. header=True
Tells Spark that the first row contains column names.

4. inferSchema=True
Tells Spark to detect the data types of columns, such as integer, decimal, or string.

5. StringIndexer?
It converts text categories into numerical labels

6. VectorAssembler
VectorAssembler combines multiple independent columns into one vector column. Spark ML algorithms expect independent features to be provided together in this vector format.

7. StandardScaler
StandardScaler scales the features so they are on comparable scales. This is useful for algorithms such as K-Means, which use distances between data points.

8. randomSplit()
Splits a DataFrame into separate datasets, usually for training and testing the model.

9. train_data and test_data
train_data is used to train the model, while test_data is used to check how well the model performs on unseen data.

10. DecisionTreeClassifier
A supervised machine learning algorithm used for classification. It makes decisions by splitting data based on feature values.

11. LinearRegression
A supervised machine learning algorithm used to predict a continuous numerical value, such as house price.

12. LogisticRegression
A supervised machine learning algorithm used for classification. It predicts the probability of a class, such as Pass or Fail.

13. KMeans
An unsupervised machine learning algorithm that groups similar data points into clusters. The k parameter specifies the number of clusters.

14. fit()
Trains the machine learning model using the provided training data.

15. transform()
Uses the trained model to make predictions or add output columns to a DataFrame.

16. prediction
The output produced by a trained model for each input data point.

17. RegressionEvaluator
Evaluates regression models using metrics such as RMSE, MAE, and R².

18. MulticlassClassificationEvaluator
Evaluates classification models using metrics such as accuracy, F1 score, weighted precision, and weighted recall.

19. ClusteringEvaluator
Evaluates clustering results. The Silhouette score indicates how well data points fit within their assigned clusters compared with other clusters.

20. Accuracy
The proportion of predictions that the model classified correctly.

21. RMSE (Root Mean Squared Error)
Measures the typical size of prediction errors in a regression model. A lower RMSE generally indicates better predictions.

22. MAE (Mean Absolute Error)
Measures the average absolute difference between actual and predicted values. A lower MAE generally indicates better predictions.

23. R² (R-squared)
Measures how well a regression model explains variation in the target values. A value closer to 1 generally indicates a better fit.

24. Silhouette Score
Measures how well-separated the clusters are. Its value ranges from -1 to 1, and a higher score generally indicates better-separated clusters.
